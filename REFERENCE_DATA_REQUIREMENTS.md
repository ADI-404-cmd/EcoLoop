# EcoLoop — Reference Data Requirements

## 1. Purpose

This document defines the scientific, technical, regulatory and reference data required by the EcoLoop E-Waste Circularity Management Platform.

The purpose is to ensure that environmental-impact and material-recovery calculations are:

* source-backed
* reproducible
* transparent
* appropriately qualified as estimates
* traceable to their source
* separated from user/application data

EcoLoop must never fabricate scientific values when source data is unavailable.

---

# 2. Core Principle

The system must distinguish between:

### A. Reference/scientific data

Stable information used to perform calculations.

Examples:

* device weight
* material composition
* material concentration
* recovery factors
* lifecycle/environmental factors
* product lifetime information
* regulatory recovery values

### B. Application data

Data generated by use of EcoLoop.

Examples:

* user submissions
* collection records
* processing records
* collection-center records
* dashboard statistics

These two data groups must remain logically separate.

---

# 3. Data Source Hierarchy

Reference data should be selected using the following priority.

## Tier 1 — Government / International Organizations

Preferred sources:

1. UNITAR / ITU — Global E-waste Monitor
2. European Commission Joint Research Centre (JRC)
3. Central Pollution Control Board (CPCB), India
4. Ministry of Environment, Forest and Climate Change (MoEFCC), India
5. UNEP
6. US EPA where relevant

## Tier 2 — Peer-reviewed scientific literature

Use for:

* material composition
* metal concentrations
* recycling/recovery rates
* lifecycle impacts
* environmental factors

## Tier 3 — Manufacturer specifications

Use primarily for:

* exact model weight
* dimensions
* battery information
* release year
* technical characteristics

Manufacturer material-composition information may also be used where the manufacturer explicitly publishes it.

## Tier 4 — Other technical sources

Use only when the above sources do not provide suitable data.

Every such source must be documented and reviewed before being used for scientific calculations.

# 5. Confirmed Source Set

## SOURCE-001 — Global E-waste Monitor 2024

Organization:

UNITAR / ITU

Purpose:

Global e-waste baseline and high-level material/resource context.

Confirmed information:

* 62 million tonnes of e-waste generated globally in 2022
* 22.3% documented as properly collected and recycled
* approximately 31 million tonnes of metals embedded in e-waste
* approximately 17 million tonnes of plastics
* approximately 14 million tonnes of other materials
* 93 million tonnes CO2-equivalent emissions avoided through formal e-waste management in the report's global assessment

Use this source for:

* homepage/global statistics
* project introduction
* global context
* high-level material/resource statistics
* explaining the importance of formal collection and recycling

DO NOT use the global averages directly as the material composition of an individual smartphone/laptop/etc.

Source:

UNITAR / ITU, Global E-waste Monitor 2024.

# 6. SOURCE-002 — JRC Environmental Impacts of Electronic Devices

Organization:

European Commission Joint Research Centre

Document:

“An overview of environmental impacts of electronic devices”

Main product groups:

* laptops
* smartphones
* tablets

Lifecycle stages considered:

1. mining and raw-material production
2. processing, assembly and transport
3. use
4. end-of-life, including collection/disposal/recycling

Use this source for:

* lifecycle-impact methodology
* explaining why manufacturing/material extraction matters
* understanding reuse and lifetime-extension scenarios
* environmental-impact context for smartphones/laptops/tablets

DO NOT convert this into a universal “kg CO2e per kg e-waste” factor.

Environmental impacts depend on product, lifecycle stage, geography, assumptions and system boundary.

# 7. SOURCE-003 — JRC Smartphone Lifecycle Study

Document:

“Reducing the carbon footprint of ICT products through material efficiency strategies: a life cycle analysis of smartphones”

Use this source for smartphone lifecycle scenarios.

The study reports that extraction and processing of materials plus manufacturing make major contributions to smartphone carbon footprint.

It reports a modeled smartphone carbon footprint of 10.7 kg CO2-equivalent/year under a biennial replacement assumption.

It also reports an end-of-life recycling contribution of approximately -0.8 kg CO2-equivalent/year within its specific methodology.

IMPORTANT:

These values are NOT universal smartphone recycling factors.

They are scenario-specific LCA results and must only be used if EcoLoop explicitly identifies the corresponding scenario and methodology.

Do not expose:

“Smartphone recycling saves 0.8 kg CO2”

as a generic claim.

Instead, if used, describe the result as:

“Reference LCA scenario based on JRC methodology.”

# 12. SOURCE-008 — CPCB EPR Certificate Framework

CPCB publishes percentages of recoverable key metals for categories of electrical/electronic equipment for EPR certificate generation.

The framework includes key metals such as:

* Au
* Cu
* Fe
* Al

These values must NOT automatically be treated as generic physical material composition.

They are specifically associated with the CPCB EPR certificate methodology.

Therefore the backend must store them separately as:

```text
cpcb_epr_recoverable_metal_factor
```

and NOT:

```text
general_device_material_composition
```

This distinction is mandatory.

# 16. Smartphone Material Composition

A JRC source provides the following representative smartphone composition:

```text
Silicon       25.0%
Plastic       23.0%
Iron          20.5%
Aluminium     14.0%
Copper         7.0%
Lead           6.0%
Zinc           2.0%
Tin/Nickel     1.0%
```

This totals 98.5%, with remaining material/components represented by other materials not captured by the simplified list.

IMPORTANT:

These percentages are representative reference data from the cited JRC source.

They must NOT be presented as the exact composition of every smartphone.

Backend representation should therefore include:

```text
device_category = smartphone
data_type = representative_material_composition
source_id = SOURCE-002
confidence = medium
```

If a more specific model-level composition is found later, it should take precedence.

# 25. Material Recovery

The system must distinguish:

```text
material_present
```

from:

```text
potentially_recoverable_material
```

Formula:

```text
material_present =
total_device_mass × material_fraction
```

Then:

```text
potentially_recoverable =
material_present × recovery_factor
```

The recovery factor must come from a documented source.

If no defensible recovery factor exists:

```text
potentially_recoverable = unavailable
```

Do NOT silently assume:

```text
recovery_factor = 100%
```

---

# 26. CPCB Key-Metal Recovery

CPCB's EPR certificate framework provides recoverable key-metal percentages for specified EEE categories.

These values may be used as an India-specific regulatory reference when the user's device maps unambiguously to the relevant CPCB category.

The backend must store:

```text
factor_type = CPCB_EPR_RECOVERABLE_METAL
```

rather than treating it as generic material composition.

The calculation should be clearly labelled:

**“CPCB EPR reference estimate”**

when applicable.

---

# 27. Environmental Impact Data

Environmental impact is the most sensitive part of the calculator.

Do NOT implement:

```text
CO2e = e_waste_kg × universal_factor
```

unless a credible source explicitly provides such a factor and its scope is applicable.

Instead, use scenario-based lifecycle data.

Potential scenarios:

```text
continued_use
reuse
refurbishment
formal_recycling
improper_disposal
```

The backend must store:

```text
metric
value
unit
scenario
functional_unit
system_boundary
geographical_scope
source
confidence
```

---

# 28. CO2e Calculation

CO2e should only be calculated when an appropriate source-backed factor exists.

Possible structure:

```text
avoided_CO2e =
baseline_scenario_CO2e
-
selected_scenario_CO2e
```

The backend must not claim that this represents actual measured emissions.

Use wording:

**Estimated CO2e difference under the referenced scenario.**

If no compatible source exists:

```text
co2e = null
availability = false
reason = "No compatible source-backed factor"
```

The frontend should show:

**CO2e estimate unavailable for this device/category.**

This is preferable to unsupported precision.

---

# 29. Age Data

Required user input:

```text
purchase_year
```

or:

```text
approximate_age_range
```

If purchase year is available:

```text
age_years =
current_year - purchase_year
```

Age does NOT directly modify material composition.

For example:

A 2 kg laptop does not become 1.5 kg of recoverable material simply because it is 5 years old.

Age influences:

* lifetime-extension recommendation
* reuse/refurbishment decision
* lifecycle scenario
* confidence
* interpretation of continued use

# 31. Circularity Recommendation

The system should recommend a pathway using:

```text
age
condition
device category
known repairability information
available reuse/refurbishment option
end-of-life intention
```

General hierarchy:

```text
Continue use
      ↓
Reuse
      ↓
Repair
      ↓
Refurbishment
      ↓
Component recovery
      ↓
Material recycling
      ↓
Disposal
```

This hierarchy should be presented as a project decision-support framework.

The recommendation should never claim that one route is universally optimal in every circumstance.

# 33. Confidence Model

## HIGH

Exact model data available and supported by strong source data.

Example:

```text
Exact model
+
manufacturer weight
+
applicable scientific composition
+
applicable recovery factor
```

## MEDIUM

Exact model not fully supported, but reliable category-level data exists.

Example:

```text
Known smartphone
+
category material composition
+
category recovery data
```

## LOW

Calculation relies heavily on broad estimates or user-provided information.

Example:

```text
Unknown model
+
user weight
+
broad category data
```

If a critical input has no credible reference:

```text
UNAVAILABLE
```

rather than LOW.

# 36. Recommended MVP

Do not attempt to support every electronic device in the first version.

The scientifically safer MVP is:

### Smartphone

Strong reference data available.

### Laptop

Strong lifecycle/material-efficiency literature exists, but composition/recovery factors must be verified before numerical implementation.

### Monitor

Can potentially use manufacturer-specific composition where applicable.

### Television

Implement submission/collection functionality first; add numerical impact calculations only after a suitable composition dataset is verified.

This allows the application to remain useful without inventing unsupported numbers.

---

# 37. Important Scientific Integrity Rules

These rules are mandatory.

1. Never fabricate a scientific value.
2. Never hide the source of a numerical factor.
3. Never merge incompatible datasets.
4. Never present representative category data as exact model data.
5. Never present potential recovery as actual recovery.
6. Never present estimated CO2e as measured CO2e.
7. Never use a universal CO2e/kg-e-waste factor without an applicable source.
8. Never use age to arbitrarily change material composition.
9. Preserve ranges where source data gives ranges.
10. Display confidence and assumptions.
11. If a calculation is unsupported, return unavailable.
12. Keep regulatory values separate from scientific material-composition values.
13. Keep reference data separate from application/user data.
14. Version the reference dataset and calculation methodology.
15. Make all scientific calculations reproducible.

---

# 38. Recommended Reference Dataset Versioning

Use:

```text
reference_dataset_version = 1.0
calculation_methodology_version = 1.0
```

When scientific reference data changes:

```text
reference_dataset_version = 1.1
```

Previous calculations should retain the version used at the time.

This makes results reproducible.

---

# 39. Final Goal

EcoLoop is not intended to replace a professional Life Cycle Assessment tool.

It is an educational decision-support and e-waste management application that uses documented reference data to provide:

* estimated e-waste mass
* material composition
* potential material recovery
* circular-pathway recommendations
* selected environmental indicators
* transparent assumptions
* source traceability
* confidence levels

The system must prioritize credibility and transparency over producing a numerical answer for every possible device.
